# 模板复刻风格迭代记录（悯农 × AI工作分享PPT_v2）

> 目标：把"任意上传 PPTX 模板 → 复刻其视觉风格 → 换成用户主题"这条链路，做到生成结果**在视觉上尽量接近原模板**。
> 本文记录一次完整的自动化"生成 → 与原模板视觉比对打分 → 迭代"闭环，如何把视觉保真度从"崩坏"提升到 **~83/100（同系列可辨识）**。
> 参照模板：`AI工作分享PPT_v2_20260717_014910.pptx`（深 navy 科技风，20 页）；测试主题：李绅《悯农》。

## 1. 方法：让"评分"驱动迭代

核心不是"我觉得好看就行"，而是建立一个**可量化、可复现的评分闭环**：

```
提取模板画像 → LLM 生成大纲 → 确定性渲染整册(含重主题配图) → 导出可编辑 pptx
      │                                                              │
      └──────────── 把生成页 & 原模板页都渲染成 PNG ────────────────┘
                                    │
                        多模态模型逐页视觉打分 + 列缺陷
                                    │
                        归并缺陷 → 定位根因 → 改渲染器/提取器 → 重跑
```

### 关键洞察：机械分是假象，必须用视觉分

项目内置的 `src/style-score.js`（`scoreDeck`）是**机械代理分**——只测"配色是否在调色板内、字体是否匹配、标题几何是否对齐"。它给悯农初版打了 **95.7/100**，但那一版实际是**崩坏的**（下文详述）。

> **结论**：机械分对"密度 / 收尾构件完整性 / 对比可读性"不敏感（单点页机械分 99，人评却是全场最低 76）。因此**以多模态视觉评分为真值**，机械分只作快速回归参考。这也正是本任务要用多模态模型的原因。

## 2. 评测工具

| 工具 | 作用 |
| --- | --- |
| `scripts/benchmark-template-style.js` | 已提交的可复现回归：用"悯农"跑自由 SVG 基线 vs 画像渲染，输出机械分与 pptx |
| `.debug/vision-eval.js`（scratch） | 用配置的多模态模型（`gpt-5.6-terra`）逐页给"是否像同一模板"打分（palette/typo/layout/legibility + 缺陷清单），并发+重试 |
| `visual-audit` Workflow（scratch） | **多评审团**：每页 3 个独立视觉评审并行打分后取平均（消除单评审 ±10 的噪声），再由综合 agent 归并去重缺陷、按严重度排序、给可落地的修复建议 |
| `.debug/lab.js` / `e2e.js` / `dump-pages.js`（scratch） | 渲染对照图、真实生图重主题端到端、导出逐页 PNG |

> scratch 工具在 `.debug/`（gitignored），是本次迭代的仪器；产品级可复现评测是 `scripts/benchmark-template-style.js`。

## 3. 迭代时间线与分数

视觉分 = 多评审团（3 评审/页取平均）的 `match_overall` 全册均值。

| 轮次 | 改动 | 视觉分 |
| --- | --- | --- |
| 起点 | 原代码直接跑悯农 | 机械分 95.7，**实测崩坏** |
| R1 | token 去硬编码 + 深色卡片系统重写 + 真实章节页检测 | **78** |
| R2 | 底部金句条 + 卡片双级文字 + 线性图标 + 章节双语眉题 + 页脚 NN/TT | **83** |
| R3 | 阶梯→单块暗罩、满高卡片、内容 kicker、分隔线归位 | **83（进入平台期）** |
| 导出修复 | 折行 / 条纹 / 拉伸 三处"预览≠导出"破绽（见 §5） | — |

逐页最终视觉分（R3，3 评审平均）：封面 84 · 章节 84/85 · 正文 85/83/84 · 单点页 80。gpt-5.6-terra（产品自评模型）同期从 80→84→86。

## 4. 根因与修复目录

### R1：从"崩坏"到"同系列雏形"（78）
起点实测三大崩坏（机械分完全没抓到）：

1. **正文卡片硬编码 warm-retro 米色**（`#FBF7EE/#EFE6D2`），压在深 navy 上冲突；且 `surface/primary` token 在深色主题下被选成浅色 → **浅字压浅卡＝完全看不见**。
   - 修：`template-profile.js` 新增 `deriveTokens`——按**对比度**推导 `ink/muted/panel/accent`（深浅主题通吃），杜绝任何写死色值。
2. **章节过渡页误用了模板第 19 页（一张图表页）当背景**，悯农"第一章/第二章"渲染成一堆空框+标题。
   - 修：`bake.js` 章节页检测改为「**满幅插画 + 文本对象 ≤12**」——找回模板真实的 5 张插画分隔页（原检测阈值 ≤6 把 7 个文本对象的分隔页漏掉了）。
3. **渲染器整体是 warm-retro 版式**。
   - 修：`template-renderer.js` 重写为**纯 token 驱动的深色卡片系统**：深面板卡片 + 顶部蓝/琥珀彩条 + 编号 + 浅色标题 + 灰描述；封面/章节用烘焙底图叠标题；章节超大编号。

### R2：补齐模板标志性构件（→83）
多评审团指出：正文"太稀疏、缺模板的结构化构件"。据此：
- **底部金句收束条**：把大纲每页最后一条要点当作 takeaway，做成"琥珀左竖条 + 加粗结论"的底部条（模板招牌构件）。
- **卡片双级文字**：把要点在首个逗号/冒号处拆成"加粗小标题 + 灰色描述"，复现卡内层次（无需编造内容）。
- **线性图标**：每卡右上角一个确定性几何图标补密度。
- **章节双语眉题**：`第一章` → `CHAPTER 01 · 第一章`。
- **统一页脚**：章节走标 + `NN / TT` 页码 + 细分隔线；`generate-deck.js` 让内容页继承所属章节。

### R3：平衡与质感微调（83，平台期）
- **卡片满高填充**：解决"卡片挤在中上部、大片竖向留白"。
- **内容页 kicker**：标题行右侧加"章节号·章名"补眉标层。
- **分隔线归位**：封面/章节的强调线从"上方短粗条"改为细长线、位置对齐模板。

> 平台期原因：悯农大纲每页仅 3 条短句，**内容天然比原模板稀疏**，非渲染器所能补足。继续冲 90+ 的最大杠杆是让大纲产出"每页 3–4 条小标题+描述"的结构化内容。

## 5. 导出保真（预览==导出）修复

真实打开导出的 pptx 后暴露三处"预览对、导出错"的破绽，逐一根因修复：

| 现象 | 根因 | 修复 |
| --- | --- | --- |
| 文字二次折行、排版错乱 | 重写渲染器时漏了 `<text>` 的 `data-box-w`，`svg-to-pptx` 退回估算宽度偏窄，PowerPoint 二次折行 | 每个 `<text>` 带上实际版面宽度 `data-box-w`；`svg-to-pptx` 文本框设 `wrap=false`；`pptx-painter` 透传 |
| `01/02` 变成 `1/2` | `svg-to-pptx` 的 XML 解析器把 `"01"` 当数字读成 `1`（丢前导零） | 解析器加 `parseTagValue:false` |
| 封面/章节遮罩一条条横纹、割裂 | 用多层半透明矩形叠"伪渐变"，重叠边缘二次叠色成横纹；单块平色又太割裂 | `bake.js` 新增 `bakeScrim`：Chrome 渲染 CSS 渐变为**透明底 alpha 渐变 PNG**（`--default-background-color=00000000`），以整幅 `<image>` 叠加；预览与导出消费同一张 PNG |
| 方形插画被拉伸/压扁 | 生图为 1024×1024 方图，全幅放进 16:9 框；pptxgenjs 对 data-URI 图 `sizing:cover` 读不到原始尺寸（srcRect 全 0）仍拉伸 | `generate-deck.js` 生成后按画布比例 **16:9 居中裁剪**再嵌入；SVG 的 `preserveAspectRatio=slice` 预览遵守、导出不遵守，故不能依赖它 |

## 6. 复现方法

```bash
# 基线机械分 + 画像烘焙（需本机 Chrome/Edge，或设 KING_PPT_BROWSER）
node scripts/benchmark-template-style.js "AI工作分享PPT_v2_20260717_014910.pptx" .tmp-style-eval/ai-v2-baseline

# 模型配置：在 ~/.king-ppt 或项目 .king-ppt/config.json 绑定
#   chat+vision → 一个多模态模型；image → 一个生图模型（OpenAI 兼容端点）
# 视觉评分与端到端见 .debug/vision-eval.js / e2e.js（本地仪器）
```

产品链路：上传 pptx → `extract.js`+`template-profile.js`（烘焙背景+渐变遮罩+推导 token）→ `generate-outline.js` → `template-renderer.js`（+重主题配图）→ `svg-to-pptx.js` 导出原生可编辑 pptx；有画像走确定性渲染，无则退回自由 SVG。

## 7. 结论与剩余杠杆

- 从"崩坏（机械分 95.7 的假象）"到"**同系列可辨识 ~83/100**"，且**全程去硬编码**——对任何深/浅色模板通用。
- 剩余杠杆（冲 90+）：①大纲结构化增密（最大）；②单点页布局；③卡片顶条圆角贴合；④背景细网格纹理（需用 line/circle 近似，渐变会被 sanitize 剥离）。
